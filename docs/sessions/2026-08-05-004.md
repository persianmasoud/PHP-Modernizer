Title:
Rule Engine Concept and Version Migration Logic


## Discussion

PHP Modernizer started as a PHP compatibility analyzer.

During architecture evolution, the Analyzer concept was separated from migration knowledge.

The Analyzer should not contain all migration rules directly.

The Analyzer is responsible for detecting code elements and collecting technical information.

The Rule Engine is responsible for understanding migration requirements based on:

- Source PHP version
- Target PHP version
- Migration path
- Compatibility rules
- Security rules
- Database rules
- Charset rules


## Analyzer Responsibility

Analyzer responsibilities:

- Scan source code
- Detect functions, classes, syntax and structures
- Collect information
- Create analysis results


Analyzer should not contain migration knowledge.

Example:

Analyzer detects:

mysql_connect()

Rule Engine decides:

mysql_connect() is removed after PHP 5.6 and requires migration.


## Rule Engine Concept

Rules represent migration knowledge.

A rule can define:

- Source version
- Target version
- Affected feature
- Rule category
- Severity
- Migration suggestion
- Validation requirements


## Version Migration Path

Migration should support different paths.

Examples:

PHP 5.6 → PHP 8.2

PHP 7.4 → PHP 8.4

PHP 8.1 → PHP 8.3


The system should understand version differences instead of only comparing two versions.


## Rule Categories

Future rule categories may include:

- PHP compatibility rules
- Removed functions
- Syntax changes
- Extension changes
- Configuration changes
- Security rules
- Database compatibility rules
- Charset rules


## Future Expansion

The architecture should focus on PHP modernization.

However, reusable concepts such as:

- Analyzer framework
- Rule engine
- Migration workflow
- Validation system

may support other modernization domains in the future.


## Decision Preparation

The following topics require further design before implementation:

- Rule data structure
- Rule storage format
- Rule execution process
- Analyzer and Rule Engine communication
- Automatic fix capability
- Validation mechanism
