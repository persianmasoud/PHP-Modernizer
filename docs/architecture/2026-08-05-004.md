# Architecture: Rule Engine Component Architecture

Date:
2026-08-05

Title:
Rule Engine Component Architecture


## Overview

PHP Modernizer uses a Rule Engine component to manage modernization knowledge.

The Rule Engine separates migration decisions from code analysis.

This allows the platform to support multiple PHP versions, different migration scenarios, and future modernization capabilities.


## Component Position

The Rule Engine is located between Analyzer and Issue generation.

Architecture flow:

Source Code

↓

Scanner

↓

Analyzer

↓

Rule Engine

↓

Issue Model

↓

Reporter

↓

Migration Workflow


## Responsibilities


### Analyzer

The Analyzer is responsible for:

- Detecting code structures
- Finding technical patterns
- Collecting source information
- Providing analysis data


The Analyzer does not decide migration actions.


### Rule Engine

The Rule Engine is responsible for:

- Loading available rules
- Matching rules with analysis results
- Evaluating compatibility
- Creating modernization findings


### Rule

A Rule represents a specific modernization requirement.

A Rule contains knowledge about:

- Problem definition
- Version compatibility
- Severity
- Recommendation
- Validation requirements


## Rule Execution Flow

The execution process:

1. Analyzer scans the application.

2. Analyzer produces analysis information.

3. Rule Engine receives analysis data.

4. Matching rules are evaluated.

5. Issues are created.

6. Reports are generated.


## Rule Categories

The architecture supports multiple rule categories:

- PHP compatibility
- Deprecated features
- Removed functions
- Security issues
- Database compatibility
- Charset problems
- Code quality


## Extensibility

The Rule Engine must support:

- Adding new rules
- Updating existing rules
- Custom rules
- Version-specific rules
- Community contributed rules


The core engine should not require modification when new rules are added.


## Future Integration

The Rule Engine architecture prepares the system for future features:

- Automatic fix generation
- Safe code transformation
- Migration planning
- Validation after changes


## Design Principle

The main principle:

> Analysis discovers facts. Rules provide knowledge. Migration workflow applies decisions.


## Reason

A dedicated Rule Engine creates a scalable foundation for PHP Modernizer.

It allows the project to evolve from compatibility analysis into a complete modernization platform while maintaining a clean and maintainable architecture.
