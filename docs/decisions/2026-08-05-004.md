# Decision: Rule Engine as Migration Knowledge Layer

Date:
2026-08-05

## Decision

PHP Modernizer will separate migration knowledge from the Analyzer engine.

The Analyzer is responsible for detecting code structures and collecting technical information.

The Rule Engine is responsible for applying migration knowledge based on:

- Source PHP version
- Target PHP version
- Migration path
- Compatibility requirements


## Analyzer Responsibility

Analyzer components should:

- Scan source code
- Detect functions, classes, syntax and structures
- Collect analysis information
- Generate analysis results

Analyzer components should not contain migration rules directly.


## Rule Engine Responsibility

Rules represent migration knowledge.

Rules can define:

- Affected feature
- Source version
- Target version
- Compatibility status
- Severity
- Migration suggestion
- Validation requirements


## Version Migration Support

The Rule Engine should support migration between different PHP versions.

Examples:

PHP 5.6 → PHP 8.2

PHP 7.4 → PHP 8.4

The system should understand version differences instead of only performing direct comparisons.


## Future Expansion

The first goal of PHP Modernizer remains PHP application modernization.

However, the architecture should allow future expansion of reusable concepts such as:

- Analyzer framework
- Rule system
- Migration workflow
- Validation engine


## Reason

Migration tools require maintainable and extensible knowledge management.

Separating rules from analysis logic allows:

- Adding new PHP versions
- Adding new compatibility rules
- Supporting custom migration scenarios
- Expanding the platform without changing the core engine
