# Decision: Rule Model Architecture

Date:
2026-08-05

Title:
Rule Model as Independent Migration Knowledge Entity


## Decision

PHP Modernizer will define Rule as an independent architecture component.

Rules will represent modernization knowledge and will be separated from Analyzer implementation.

The Rule system will allow PHP Modernizer to detect, explain, and manage migration requirements in a structured way.


## Rule Responsibility

A Rule is responsible for defining:

- What feature is affected
- Which versions are involved
- What compatibility problem exists
- How severe the issue is
- What migration suggestion should be provided
- What validation is required


## Separation Principle

The Analyzer and Rule Engine have different responsibilities.

Analyzer:

- Detects code patterns
- Collects technical information
- Produces analysis data


Rule Engine:

- Evaluates detected information
- Applies migration knowledge
- Creates modernization issues


Rules should not depend on how detection is performed.


## Rule Extensibility

The Rule model should support future categories including:

- PHP compatibility rules
- Deprecated features
- Removed functions
- Syntax changes
- Security rules
- Database rules
- Charset rules
- Code quality rules


New rules should be addable without modifying the core engine.


## Rule Version Awareness

Rules should support version-based decisions.

Examples:

PHP 5.6 → PHP 8.2

PHP 7.4 → PHP 8.4

A rule should be able to define:

- Source version
- Target version
- Migration impact


## Future Capabilities

The Rule model should allow future support for:

- Automatic fix suggestions
- Automated code changes
- Validation after migration
- Custom user-defined rules
- Community contributed rules


## Reason

A structured Rule Model allows PHP Modernizer to evolve from a simple compatibility checker into a scalable modernization platform.

Separating migration knowledge from processing logic improves:

- Maintainability
- Extensibility
- Version support
- Safe automation
